# JSONForm `showWhen` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A `form` item in a race's JSONForm may carry `"showWhen": { "<schema key>": "<value>" }`; the SPA Questions card hides the field unless that answer matches, and the admin race form rejects required conditional fields.

**Architecture:** One pure helper, `hiddenKeys(jsonform, answers)`, in `frontend/src/features/questions/validate.ts`. The renderer, `buildPayload` and the answered count all read it. `RaceValidator#validate_jsonform` gains a structural check. The server's answer handling and the legacy flow do not change.

**Tech Stack:** React 19 + TypeScript, Vitest + Testing Library + MSW, Rails 8 with RSpec, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-20-showwhen-design.md` (issue #334). Worktree `.claude/worktrees/feature+334-show-when`, branch `feature/334-show-when`, from `origin/main`. This is not a stacked PR; open it against `chiditarod/dogtag` and never merge.

## Global Constraints

- Key name is exactly `showWhen`, with exactly one pair `{ "<schema key>": "<string value>" }`, compared by exact string equality.
- `showWhen` is valid only if: a non-null, non-array object; exactly one entry; the value is a string; the key is in `schema.properties`. Anything else is ignored and the field stays visible.
- Only keyed `form` items carry `showWhen` (including keyed items nested inside fieldsets). No expressions or operators.
- Do not change `JsonForm.filter_answers`, `TeamValidator`, or `vendor/assets/javascripts/jsonform.js`.
- Do not pass modified schema copies to `validateAnswers` (`validate.ts` caches on the schema object in a `WeakMap`).
- Gemfile, `config/initializers`, `config/environments`, `config/application.rb` and `spec/spec_helper.rb` are off limits without asking.
- Ruby: double quotes, no trailing whitespace, blank line at end of file. Frontend strings go through `t()` in `frontend/src/locales/en.ts` (none are expected).
- Frontend tests: `npm --prefix frontend test -- --run <path>`. RSpec: `bundle exec rspec <path>`. Commit messages end with `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.

## Review Focus

Inputs the spec implies but no requirement line spells out, most likely first. Each is pinned by a test in the task named.

1. A saved answer for a field that loads hidden (stale server answer): it is dropped on Save and not counted in "N of M answered". (Task 3)
2. A chain: B is shown by A, C is shown by B. A hides B, so C is hidden even though B's stale draft still equals C's trigger. (Task 1)
3. A cycle or self-reference (A shows when B = x, B shows when A = y; or A shows when A = x): no hang, both stay visible. (Task 1)
4. `showWhen` naming a key that is not in the schema, or a bad shape (array, two pairs, non-string value): the field stays visible. (Tasks 1 and 2)
5. A required field with `showWhen` nested inside a fieldset, or with a malformed `showWhen`, is still rejected by the race form. (Task 4)

### Task 1: `hiddenKeys` helper

**Files:**
- Modify: `frontend/src/features/questions/types.ts` (add `showWhen?: unknown` to `JsonformItemObject`; it is `unknown` because untrusted payloads can put anything there)
- Modify: `frontend/src/features/questions/validate.ts` (add the helper)
- Test: `frontend/src/features/questions/validate.test.ts`

**Interfaces:**
- Produces: `export function hiddenKeys(jsonform: Jsonform, answers: Answers): Set<string>`. It returns the schema keys that are currently hidden. A key with no valid `showWhen` is never in the set. `answers` are the current answers with schema defaults already applied (callers pass `value` from `questions-card.tsx`).

- [ ] **Step 1: Write failing tests in `validate.test.ts`**

A helper builds a `Jsonform` with optional string properties `a`, `b`, `c` and a form list. Tests, with assertions:
  - `hides a field until the controlling answer matches`: `c` has `showWhen: { a: "Yes" }`. `answers {a: "No"}` gives a set containing `c`; `{a: "Yes"}` gives an empty set; `{}` (unanswered) gives a set containing `c`.
  - `finds showWhen on items nested in fieldsets`.
  - `a hidden controller hides its dependents`: `b` shows when `a = "Yes"`, `c` shows when `b = "x"`. With `{a: "No", b: "x"}`, both `b` and `c` are hidden. With `{a: "Yes", b: "x"}`, neither is.
  - `cycles and self references leave every field visible`: `a` shows when `b = "x"`, `b` shows when `a = "y"`, answers `{}`, set is empty. `a` shows when `a = "x"`, set is empty.
  - `ignores a malformed showWhen`: for each of `[]`, `null`, `"Yes"`, `{ a: "Yes", b: "No" }`, `{ a: 1 }`, `{ missing: "Yes" }` (key not in schema), `c` is not in the set.
  - `has no conditions when the form list is empty` (the renderer falls back to all schema keys): set is empty.

- [ ] **Step 2: Run them and confirm they fail**

Run: `npm --prefix frontend test -- --run src/features/questions/validate.test.ts`
Expected: FAIL (`hiddenKeys` is not exported).

- [ ] **Step 3: Implement `hiddenKeys` in `validate.ts` and the type in `types.ts`**

Walk `jsonform.form` recursively (through `items`) and collect `key -> { controller, expected }` for keyed items with a valid `showWhen`; the first occurrence of a key wins. Resolve each conditional key by following its controller chain: hidden if any controller up the chain is hidden or the nearest controller's answer is not exactly `expected` (a missing answer matches nothing). If the chain loops, treat that key as visible. Leave validation behavior and the `WeakMap` cache alone.

Run: `npm --prefix frontend test -- --run src/features/questions/validate.test.ts`
Expected: PASS.
